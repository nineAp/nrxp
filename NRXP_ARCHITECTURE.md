## Место в стеке

```

        │
        ▼
   Muxer (закрыт): распределение по потокам, credit-based flow control,

        │

        │
        ▼

   маскировка под TLS / QUIC / WebRTC-RTP
        │
        ▼

```

## Мультиплексирование (закрыто)

Один зашифрованный туннель переносит произвольное число независимых
логических потоков (TCP-соединений и UDP-сессий пользователя) одновременно —
NRXP различает их по id потока в заголовке кадра (`stream_id`, поле
`FrameHeader` — само поле уже видно в открытом коде `frame.rs`, закрыт только
код, который решает, что с этим id делать: очередь по сокетам, backpressure,
переключение потока между параллельными соединениями при отказе одного из них).

Поток открывается и закрывается управляющими кадрами (`Connect`/`Close` —
типы кадров тоже уже в открытом коде); данные внутри потока идут кадрами
данных; отдельный тип кадра переносит кредиты flow-control.

## Flow control (закрыто)

Сквозной, кредитный: получатель выдаёт отправителю явный бюджет и пополняет
его по мере разбора данных, так что медленная цель не может заставить туннель
буферизовать без предела. Окно на поток стартует с малого значения и растёт
по измеренному RTT — конкретная формула роста и стартовые/предельные значения
не публикуются: это то же семейство риска, что и калибровка паддинга —
поведенческая сигнатура, наблюдаемая по throughput отдельных потоков.

## Multipath и отказоустойчивость (закрыто)

Сессия может идти по нескольким параллельным несущим соединениям
одновременно, а не по одному. Поток закреплён за одним соединением ради
порядка доставки; при отказе соединения поток переезжает на живое соседнее, а
кадр в полёте переотправляется. Логика выбора, когда считать соединение
отказавшим, и алгоритм миграции потоков — закрыты: это конкретная инженерная
реализация (таймауты, эвристики health-check), а не идея, и как реализация
она представляет коммерческую ценность сама по себе, отдельно от вопроса DPI.

## Кадры-пустышки после хендшейка (открыто — механизм в `codec.rs::encode_cover`)

Настоящий TLS 1.3-сервер сразу после `ServerHello` присылает несколько
килобайт сертификатной цепочки — это видно на проводе как несколько
TLS-записей `ApplicationData`, отправленных сервером первым. NRXP решает это
отдельным типом кадра (`FrameType::Cover`), который не несёт полезной
нагрузки. Сам механизм и код теперь открыты; длины, которыми наполняется
cover-flight, приходят из `tlseng::decoy::CoverFlight` (тоже открыт, без
калибровки конкретных сертификатных цепочек).

## Версионирование

Протокол несёт номер версии, заявляемый клиентом при хендшейке — это
позволяет включать несовместимые для старых клиентов изменения только для
тех сторон, которые заявили версию, где такое изменение уже поддерживается.
Механизм и сами константы версий (`net_consts::PROTOCOL_VERSION*`) уже
открыты — версия протокола не даёт наблюдателю ничего, что можно
использовать для детекта: это число появляется только внутри уже
расшифрованных данных.
